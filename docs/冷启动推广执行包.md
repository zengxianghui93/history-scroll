> 适用前提：0 粉、单人、不投钱、**不改代码**（导出图贴码 / 埋点 / 首页换城由开发者后续自行补）。

## 0. 为什么 `demand.md` 照着做会觉得难

那份文档的推广部分只有 3 条，问题不在执行，在于它写的是**「有粉丝之后怎么运营」**，不是**「0 粉怎么来第一批人」**：

| 原文建议 | 隐含前提 | 0 粉时的现实 |
|---|---|---|
| 「等有几百粉丝且有人问怎么玩时，主页简介置顶」 | 已有几百粉丝、有人主动问 | 没有人问，这一步永远等不到 |
| 「在评论区让用户投票选下一座城」 | 评论区有人投票 | 没人投票，且**西安其实已经上线**，再问「下一座画哪里」和产品现状自相矛盾 |
| 「用小号在评论区引导去微信搜」 | 认为这是低成本技巧 | ⚠️ **按 2026 平台规则是高风险，别做**（见第 6 节） |
| 「别只发插画，要发情绪价值」 | 只给了公式 | 没给标题、没给关键词、没给发布清单、没给节奏、没给衡量方式 |

还有两处结构性遗漏：

1. **完全没提微信搜一搜**——这是小程序唯一不依赖粉丝、不依赖推荐算法、零成本的确定性入口，你 `sitemap.json` 已经全量开放收录，等于门开了没人推。
2. **把「发内容」和「引流」混成一件事**。0 粉阶段根本不需要「引流」（也没有流可引），需要的是让用户**搜得到**、让盖过章的人**有东西可晒**。

所以换一套定义：

- **微信生态内 = 转化**（能直接进小程序：搜一搜、分享卡片、朋友圈、群）
- **小红书 = 被搜到 + 长期种草**（不跳转、不导流、不指望当场转化）
- **抖音 = 拉新认知**（已跑通的讲解动画模板，不承担转化）
- **线下点位 = 后期**（需要有内容和用户数据做背书再去谈）

## 1. 今天第一件事：微信搜一搜配置（约 20 分钟，后台操作，零代码）

小程序名称权重最高，但**一年只能改 2 次**，且「大千小卷」是品牌词、没人会搜——**不建议改名**。真正该动的是下面三项。

### 1.1 简介（前 28 个字决定搜索结果点击率）

直接用这段（可微调）：

```
手绘城市画卷＋地标盖章打卡：点开北京、西安的地标故事，边逛边集章，导出属于自己的探索手册。19 处北京地标、3 张长卷，每处附冷知识与现场观察路线；逛一座城，集一套别人抄不走的章。
```

前 28 字里已含「城市画卷 / 盖章打卡 / 地标」三个核心词，后半段覆盖长尾。

### 1.2 后台 10 个自定义关键词（一次性填好）

> 规则：小程序后台可配 **10 个**自定义关键词，审核约 **7 个工作日**，每月修改次数有限（约 3 次）。别浪费，一次填准。

按「低竞争长尾 + 明确意图」选，不要抢「北京旅游」这种大词：

```
北京集章
北京盖章攻略
故宫盖章
城市打卡
北京citywalk
中轴线攻略
故宫冷知识
北京地标打卡
集章小程序
城市探索手册
```

选词依据：搜这些词的人心里已经有一个具体疑问；而「北京旅游」这类词既抢不过大号，进来的人也不会盖你的章。

### 1.3 页面标题（后续顺手做，不列入今天）

`wx.setNavigationBarTitle` 让详情页标题带上地标名，例如「故宫 · 太和殿屋顶的第十只小兽」，可覆盖「故宫 脊兽」「太和殿 走兽」这类搜索。这条需要改代码，等你自己补那三件时一起做即可。

### 1.4 别动的东西

`sitemap.json` 已全量开放收录、主包排除大图后约 0.43MB、云资源映射规范——这些是加分项，别为了「SEO 优化」去改。

## 2. 第一批 6 条搜索型笔记（可直接复制，够发三周）

**原则**：不追爆款、不赌推荐流。小红书搜索流量占比约 30–65%，0 粉账号靠精准长尾词卡位；前 10–15 篇**高度垂直**（只做「北京地标冷知识 / 集章」），别今天发美食明天发摄影，否则账号标签乱掉。

**共同规范**：
- 标题 20 字内、关键词前置、写成「答案」而不是「感想」

- 标签 5–8 个：1 个核心词 + 4–5 个长尾 + 1 个热点词
- 首图**直接用项目现成插画/内容页截图**，不用新画
- **小红书版本一律不出现**：微信、二维码、小程序码、外链、谐音暗引、「去搜 XX」。转化交给微信搜一搜，别在这里硬导

## 3. 让已有的传播物真正带人（不改代码）

你已经有探索手册导出（封面 / 单页 / 分段长图 / 朋友快照隔离），比一张卡片完整得多。**缺的不是再做一张图，是把它发出去**。

### 3.1 种子用户（今天就能做，比发任何笔记都值）

找 **20 个朋友**，请每人走一遍：`点一个地标 → 看一段 → 盖一个章 → 导出手册`，只回一句「哪一步卡住了」。
收获：20 个真实用户、几张真实的 UGC 手册图、一份最真实的流程反馈。这是所有动作里唯一「干了就一定有结果」的。

### 3.2 分发场景与配文

| 场景 | 发什么 | 配文示例 |
|---|---|---|
| 朋友圈 | 自己盖了几枚章的**手册导出图** | 「把北京逛成了一本小册子。19 处地标，先盖了 6 枚，剩下的慢慢来。」 |
| 微信群（本地/文旅/手账/摄影，3–5 个群即可） | 手册图 + **顺手转发小程序卡片**（右上角转发，比图片多一步直达） | 「自己做的城市打卡小东西，北京和西安能逛，点开能盖个章，帮忙看看顺不顺手。」 |
| 小红书 | 手册图当第 ⑤ 条笔记首图 | 见上，不带任何导流字样 |
| 回答别人的集章提问 | 直接答问题，不硬推 | 有人问「北京哪儿能盖章」时，认真答完再顺带提一句自己的数字章 |

**关键**：微信生态内是**可以直接写「大千小卷」和直接发小程序卡片的**，零违规风险。小红书那边不要写。两个生态用两套话术，别混。

## 4. 一套素材吃四个出口（解决「持续产出太累」）

`demand.md` 让人觉得难的另一个原因，是它默认你要**持续创作新内容**。其实不用——每周只写 **1 个地标的 1 段冷知识**，改四次标题就能铺满四个出口：

| 出口 | 改法 | 耗时 |
|---|---|---|
| 小红书图文 | 冷知识 + 清单/问答标题，配现成插画 | 10 分钟 |
| 微信朋友圈 / 群 | 同一段缩成 3 行 + 手册图 + 小程序卡片 | 3 分钟 |
| 抖音讲解动画 | 丢进已跑通的 `build_video.py` 那套（镜头推拉＋配音＋字幕），换个文案即出片 | 20 分钟 |
| 搜一搜长尾词 | 笔记标题里的关键词，同步补进公众号/知乎回答 | 5 分钟 |

**一个地标 = 四条内容，不用重新创作。** 19 个地标够铺一个季度。

三周后就能回答：搜索来的多还是分享来的多、哪条笔记真的带人。别一上来就上数据平台。

## 6. 明确别做的四件

1. **别用小号在评论区引流**。`demand.md` 第 3 条建议用小号说「去微信搜 XX」。按现行规则，小红书已上线**跨账号协同导流检测**，主号+小号联动可被判矩阵导流：轻则禁言 7 天 + 笔记下架 + 限流 30 天，重则永久封号，且关联账号同步受限。这是整份文档里唯一会让你**倒扣**的建议。
2. **别做「投票选下一座城」**。0 粉没人投，而且西安已经上线，问「下一座画哪里」反而显得产品没做完。等真有几百条评论再做。
3. **别一上来铺线下点位 / 谈合作**。没有内容数据和用户量做背书，谈不下来；等第 4 周有了「多少人盖了章」再说。
4. **别日更**。前 10–15 篇垂直比数量重要，搜索笔记生命周期 6–12 个月，慢慢发比猛发有效。
