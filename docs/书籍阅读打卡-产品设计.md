# 书籍阅读打卡小程序 · 产品设计

本文维护阅读产品的当前设计，后续直接更新对应章节，不按版本迭代堆叠需求。产品名称待定。`book` 分支用于探索此方向；城市探索文档描述原产品，不作为本产品的需求依据。

## 1. 产品定位

把想读的书，变成随时能开始的一小段阅读，让零碎时间积累成可回看的阅读痕迹。

目标用户是有阅读意愿、但时间被工作、家庭和娱乐分散的人。主要场景是午休、等人、通勤途中适宜阅读时、睡前等短暂空闲；一次阅读可以很短，不要求每天完成固定页数。

产品价值分为两部分：准确续读、舒适阅读和自动记录降低开始的阻力；书籍式纪念册让用户看见积累，愿意回来。不能把打卡次数等同于知识掌握程度，也不以用户每天分享作为成立条件。

## 2. 已确认的基本方向

- **私人书库**：个人导入、本人阅读，每个人带着自己的书积累记录。第一版不提供公共书库，不向其他用户分发上传的正文。
- **随时续读**：打开后直接看到最近在读的书和上次停留位置，减少进入正文前的操作。
- **温和激励**：帮助用户重新开始，不用中断惩罚、进度清零或羞辱文案驱动阅读。
- **半程纪念**：读到一半时给予鼓励，可自愿分享。
- **轻翻页阅读**：正文清晰、顺畅、少操作，翻页动效轻量。
- **书籍式回看**：日期、进度、可选感想组成阅读纪念册，支持生成分享图片。
- **同读**：第一版统一共读大厅，用户登录后自动加入，展示系统昵称和阅读时长，支持今日动态、本周榜、星星鼓励和元气番茄邀请。书名、正文和感想不公开。

## 3. 第一版建议范围

以下为当前设计基线；具体入口布局、技术实现和待定项在开发前确认。

| 部分 | 核心能力 | 设计重点 |
| --- | --- | --- |
| 今天／首页 | 导入首本书、最近在读、继续阅读、切换在读书 | 一个清楚的主操作，近期记录作为次要信息 |
| 阅读器 | 正文、章节定位、阅读设置、自动保存位置 | 短时间也能开始；退出与恢复可靠 |
| 书架 | 在读、已读完、暂时放下 | 可以同时读多本，不强制读完才能换书 |
| 阅读纪念册 | 按书成册、阅读痕迹、可选感想、纪念页 | 自动生成，有感想更丰富，无感想也完整 |
| 分享图片 | 日常记录、半程、读完纪念 | 用户主动生成和保存，自行分享 |

底部固定三个 Tab：阅读、同读、我的。书架和纪念册位于“我的”，阅读器为独立页面。第一版不包含自由发帖、评论、私信、多个圈子、在线书籍交易、实体印制、AI 自动代写心得。

## 4. 核心流程

### 首次使用

导入一本书 → 展示解析结果及可编辑书名 → 开始阅读 → 自动保存位置与阅读记录 → 之后可回看纪念册。

导入应明确说明支持的格式、文件限制和私人用途。解析失败要解释原因并允许重试，不生成看似成功但无法阅读的空书。文件大小、编码、重复导入、章节解析等规则需在技术方案中明确。

### 日常阅读

打开首页 → 继续最近在读 → 阅读任意一段 → 退出、切后台或中断 → 下次从保存的位置继续。

首页只展示状态为“在读”的书籍；当前书籍读完、暂停或删除后，优先续读其他在读书籍，没有在读书时显示选择书籍的起始状态，并保留书架入口。删除纪念册会隐藏该册，并将对应的在读书籍设为“暂时放下”，保留正文、进度、时长与感想；已读完状态不被改为暂停。删除正文另行确认。重新选择已读完书籍时，确认后从第一页重读，保留历史记录。

不要求先启动计时，不要求退出前手动打卡，感想始终可选。首页最多展示必要的续读信息和轻量近期记录，不堆排行榜、任务、广告式激励卡。

### 回来看与分享

从书架进入某本书的纪念册 → 翻阅日期、进度和自己的感想 → 选择一个纪念页 → 预览分享图片 → 用户主动保存与分享。

仅生成分享图片不等同于公开整本纪念册。分享落地页是否存在、具体展示什么，需另行确认；不得通过分享访问私人书籍正文。

## 5. 阅读与记录规则

### 阅读位置

- 保存章节与稳定文本位置；电子书页码随字号、屏幕变化，不作为唯一定位依据。
- 用户主动往回阅读后，下次继续其最后停留位置。
- 第一版按单设备使用设计，不实现多设备同时阅读、位置冲突选择或跨设备记录合并。当前设备最后保存的位置用于续读，不以最远位置覆盖重读位置。
- 保留离线记录联网后补传与去重；同一条记录重复提交不能重复累计时长或生成动态。
- 当前停留位置与累计阅读记录分开保存；重读不被误判为记录丢失。
- 修改字号、切后台、锁屏、异常退出后的恢复，是第一版验收重点。

### 阅读记录

- 自动记录阅读日期与位置变化，不强制手动提交。
- 快速拖动进度条、跳到末章不能直接宣称读完，更不能宣称掌握知识。
- 半程及读完的触发条件需确认；按实际阅读活动识别，避免单次跳转触发成就。
- 时长若展示，需排除后台及明显无效停留；计时定义未明确前不宣传“有效阅读分钟数”。
- 不补造过去的阅读日期，不自动编造用户感想。

### 目标与书籍状态

建议目标可选，优先提供“每周读几次”等弹性目标。用户也可不设目标直接阅读；每日页数、时长目标是否提供待确认。

书籍可标记在读、已读完或暂时放下。允许重新开始与重读；读完状态如何由阅读行为与用户确认共同决定，开发前确定。

## 6. 激励与反馈

### 日常

记录自动保存，用轻量反馈表达积累，不每次弹窗、不反复要求分享。欢迎语偶尔出现即可，续读入口始终优先。

示例：

> 欢迎回来，上次读到这里。

> 这周你读了3天。

文案中的日期与数量必须来自真实记录。断一天不清零，不使用“你又失败了”“已经落后”等表达。

### 里程碑

建议保留第一次阅读、读到一半、读完一本三个节点。半程提示在自然停顿或退出阅读后出现，不在阅读中强制打断。支持关闭、继续阅读或分享，同一里程碑不重复弹出。

半程文案示例：

> 已经读到这里了。那本一直想读的书，正在被你一点点读下去。

读完纪念体现个人积累，不作与其他用户的能力比较。未完成的书也能留下值得回看的记录。

## 7. 阅读器与视觉原则

- 正文以可读性优先，字号、行距、浅色／深色背景可调整。
- 支持轻翻页效果，建议可关闭动画；具体左右翻页、上下滚动的默认方式待确认。
- 纸纹、书脊和阴影不侵入文字、不降低对比度、不压缩有效阅读宽度。
- 封面、章节开头及纪念册充分呈现书籍感，正文避免持续强动效。
- 已导入内容尽量支持离线续读；缓存、备份与恢复范围在存储方案中明确。
- 手机单屏布局，主要操作易点，尊重安全区和系统字体变化。

## 8. 阅读纪念册

按书成册，所有册子放进个人书架。自动生成，不要求先编辑才有内容。

建议结构：封面 → 阶段性阅读记录 → 半程纪念 → 后续记录 → 读完或待续页。日常记录可按时间段聚合，避免每次打开都新增一张重复空页。日期、进度、感想的具体排版在样稿阶段确认。

有感想时展示用户原文；无感想时展示简洁记录，不用通用鸡汤冒充用户心得。纪念册在产生首条时长大于零的本机阅读记录后才展示，仅导入或仅写感想不生成空册。移除纪念册只隐藏入口，并保留正文、进度、时长和私人感想；“我的 → 设置 → 恢复纪念册显示”可逐册恢复，恢复不自动改变书籍在读状态。永久删除私人感想不属于该操作。

分享图片允许用户选择是否包含书名、日期、进度和个人感想，生成前可预览。默认不输出书籍正文，不自动公开全部阅读记录。书封和其他素材的使用权限需核对。

## 9. 私人数据与平台边界

当前按用户决定推进产品设计，暂不将平台准入核实作为设计和开发的前置步骤；此安排不代表平台已确认准入。

个人上传不等于获得对外传播授权。书籍仅供上传者本人阅读，服务端如存储文件，必须落实按用户隔离的访问控制，不用公共可读云目录保存私人书籍。私人阅读权限也不能直接沿用原城市插画的公共资源权限。

复用现有项目、小程序账号及腾讯云开发资源，在 `book` 分支设计和实现。书籍和阅读记录保存至云端，当前设备缓存正文并保存待补传记录；第一版不兼容多设备同时使用。存储容量、缓存与删除机制需明确告知用户。

复用资源不等于混用业务数据：阅读业务采用独立的数据集合和存储目录，私人书籍不能沿用城市插画的公共读取权限。不得覆盖原城市产品的数据、资源或线上业务；现有城市记录不转换成读书记录。具体权限隔离在实现方案中明确。

## 10. 共读大厅

全体用户登录后自动进入同一个大厅，取消手动加入和退出入口，旧账号再次登录时自动迁移。大厅仅展示系统昵称和记录时长，不公开书名、正文和感想。动态按用户和自然日合并；默认显示今日动态，不制造虚假的在线人数。动态与本周榜分栏，本周榜按服务器认可的时长排序、同分并列；榜单显示前 50 位，自己的本机记录另行展示，不将其宣称为云端榜单成绩。

每人对一条动态最多一颗星，可取消，不影响时长排名。元气番茄仅选择预设话语，同一对象每天一次，每人每天最多五次。进入大厅时先同步本机记录，再查询动态；不足一分钟的有效记录显示“不足 1 分钟”。首次加油产生一条星星鼓励，重复请求、取消后再次加油不重复通知；番茄继续按每日规则去重。星星和番茄共用站内未读消息，首页显示轻提示卡，不自动弹窗；用户点击查看并确认后标记已读，后续返回不重复提示。番茄接收可关闭，星星鼓励不受该开关影响；长按动态可屏蔽对方的动态和邀请。当前仅站内消息，不使用外部推送。

记录时长不代表阅读质量。正文排版并显示成功后才计时；图片页等待图片加载成功。前台阅读按毫秒累计、提交时转为整秒并保留不足一秒的余量；切后台、目录与设置面板、填写感想和读完确认弹窗、正文加载或排版失败时暂停。连续五分钟无操作后暂停，轻触或翻页仅从当前时刻恢复，不补计暂停期间。约每三十秒落盘，暂停和退出时补存，单条补传最多五分钟、超出时分段；服务端拒绝同用户重叠的计时时段并对记录编号去重，个人统计与榜单均不设置每日六小时上限。离线记录补传后更新相应记录；历史周记录不影响当前周榜单。

## 10.1 当前实现与云端准备

- 页面入口：`pages/reading-home`、`pages/book-reader`、`pages/reading-together`、`pages/reading-mine`、`pages/book-journal`。
- 运行 `npm run build:reader` 生成小程序可直接使用的 EPUB 解析模块；`npm run typecheck` 与 `npm run test:reading` 验证阅读代码。解析器支持无加密文字 EPUB 和 UTF-8 TXT，单本 10MB、解压内容 20MB、正文 100 万字以内、书架最多 30 本；EPUB 按 spine 顺序阅读，支持内嵌 PNG、JPEG、GIF、WebP 插图，按原书位置单独成页、等比完整展示；单图限 512KB，插图合计限 1.5MB，解析后图文结构限 300 万字符。外链图片、SVG 图片及加密 EPUB 明确提示不支持。正文压缩连续空行、清理行首尾空白，保留单行换行及原文分隔符，不擅自合并诗歌等内容。暂不复刻原书字体、表格及复杂版式，书架统一使用原创书封底图与书名。旧版已导入书籍可再次选择同一文件，确认更新排版后保留记录并按附近正文定位；新旧文本无法精确匹配时保留有效范围内的原偏移。
- 云端恢复入口位于首页及“我的”常用功能区。下载当前账号已完成同步但本机缺失的书籍，逐片验证后写入书架；已有本机正文不覆盖，私人记录不改写，优先保留本机待同步的最近阅读位置。未同步版本丢失时要求重新导入原文件，不能用旧云端正文静默替换。恢复期间的读写操作串行，恢复失败可重试。
- 正文按实际阅读区域宽高及字体字宽分行，行数以字号与行高计算，显示换行与原文偏移分开保存；改字号、改行距、横竖屏变化后定位回包含原阅读位置的页面。图文交界保持原文顺序；不会拆开 Unicode 代理对及常见组合字符。
- 书籍被转换为章节文本与内嵌图片数据，在云数据库 `book_content` 分片保存；本机保存同一份结构化正文。原 EPUB 文件不上传到原项目公开的插画存储目录。
- 新增 `cloudfunctions/reading` 云函数，复用环境 `cloud1-d7gp1zt48d1eda997`。由服务端从微信上下文识别用户，所有正文与记录操作校验归属。原 `exploration` 函数及城市数据不改写。
- 部署前，在云数据库创建 `book_profiles`、`book_library`、`book_content`、`book_events`、`book_days`、`book_stars`、`book_invites` 七个集合，全部设置“仅管理端可读写”（自定义 `read:false, write:false`），对照 `cloudfunctions/reading/database.rules.json`。该文件是配置清单，不会自动应用权限。客户端仅通过云函数访问，不自动创建可能使用宽松默认权限的集合。
- 为查询配置复合索引：`book_library(owner, ready)`；`book_content(owner, bookId)`；`book_days(day 升序, updatedAt 降序)`；`book_profiles(joined 升序, week 升序, seconds 降序)`；`book_stars(target)`；`book_invites(target 升序, seen 升序, createdAt 降序)`。普通单字段索引按控制台现有设置复用。
- 右键 `cloudfunctions/reading`，选择上传并部署（云端安装依赖）。本轮本地验证使用 SDK 边界适配器，不操作真实用户数据；云函数部署、数据库权限和真机端导入、翻页、授权仍需实际验收。
- 云端尚未配置时，页面明确提示同步失败，本机导入与续读可用；动态不展示演示用户。新书封随包加载，无需手动上传插画。
- 当前纪念册保存阅读日期、时长、个人感想和半程/读完节点，提供单页 Canvas 导出。分享默认隐藏书名与感想，用户勾选后才包含。删除书籍正文时保留阅读纪念册；已提供缺失书籍的云端恢复和隐藏纪念册的恢复显示，不提供多设备合并界面。

## 11. 待确认的产品决策

| 决策 | 当前建议或问题 |
| --- | --- |
| 产品名称 | 名称待定；账号与云开发资源已确定复用现有资源 |
| 导入范围 | 建议先做文字型 EPUB、TXT，PDF 与扫描版后置；文件上限、DRM 文件处理需明确 |
| 存储容量 | 云端存储、本机缓存已确定；单本大小及个人容量上限待确定；不实现多设备冲突处理 |
| 登录时机 | 是否首次可直接阅读，备份或同步时再登录？以可实现的平台能力确认 |
| 阅读方式 | 默认轻翻页还是滚动，是否提供切换？ |
| 阅读目标 | 无目标是否为默认？周频次、页数、时长如何选择？ |
| 里程碑判断 | 实际阅读活动与位置如何结合，怎样识别半程、读完和重读？ |
| 纪念册聚合 | 按次、按日还是按周组织，避免碎片记录造成冗长？ |
| 分享与隐私 | 首版仅图片分享，还是提供受控的纪念页访问？ |
| 删除与恢复 | 删除书籍时能否保留纪念册，清缓存和账号注销后如何处理？不扩展多设备迁移流程 |

## 12. 验证与实施顺序

先确认上述关键范围，再输出首页、阅读器与纪念册的具体交互方案供确认，之后实施。现有项目可复用的书籍样式、导出能力和云开发基础需检查后决定，不直接套用城市集章业务。

最小验证链路：导入一本真实想读的书 → 准确续读 → 自动记录 → 回看纪念册 → 自愿导出图片。

先由开发者本人体验，再邀请处境相近的用户小范围使用。重点观察是否主动开始第二、第三次阅读，中断后能否轻松回来，哪些步骤造成放弃；不以一次视觉好评证明长期需求。
