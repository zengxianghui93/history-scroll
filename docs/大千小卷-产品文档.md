# 大千小卷 · 产品文档

## 产品定位

大千小卷是一款用手绘画卷认识城市的微信小程序。打开就能看到一座城，从好奇的地标开始，读一段故事，记住一个下次还能认出来的细节，再用一枚印章留下探索记录。

面向对城市文化、建筑和街巷生活感兴趣的用户，也适合只有几分钟、想随手了解一处地方的人。一次打开能完成一个小发现，下次能从原来的地方接着逛。首个完整样板是北京，后续城市沿用相同的页面职责和成果规则。

## 页面结构与核心流程

底部两个入口是「探索」和「我的」。

| 页面 | 承担的任务 | 主要去向 |
| --- | --- | --- |
| 探索 · 城市画卷 | 一眼看到城市有哪些地方值得点开，知道自己已经点亮了哪些 | 地标详情、认识北京、分享画卷 |
| 地标详情 | 读懂一个地方，找到一个值得留意的细节 | 相关故事、盖章、分享；收藏主故事后可在「我的见闻」回看 |
| 认识北京 | 了解城名、历史与格局，把零散的地标放回城市脉络 | 建城史、胡同生活等城市故事 |
| 我的 · 我的城市册 | 继续上次的旅程，查看印章和收藏 | 返回上次画卷、回看地标和见闻、展开其他记录 |
| 画卷分享落地页 | 让朋友直接看到推荐地标在城里的位置 | 点开推荐地标，或横滑自由浏览 |

首次探索从画卷开始。点地标直接进入详情，读完可主动「盖印打卡」。返回画卷后，计数更新，对应地标短暂泛起暖金光并保留朱印标记。之后可以从「我的」续逛、从集章册回看地标，也可以将画卷或发现分享给朋友。

## 探索 · 北京画卷

- 首页以全屏插画为主体，顶部保留北京、点亮进度、「认识北京」和分享。用户手动横滑或点分页圆点换画卷，首访提示「左右滑看」。
- 点地标直接打开对应内容。空心圆表示待点亮，朱印表示已点亮。画卷表达城市印象与地标的大体关系，实地观察路线在有需要的详情页单独呈现。

## 城市开放状态与上线流程

当前正式版仅开放北京三张画卷与19处地标；首次进入默认北京，回访恢复北京停留页。城市是否正式开放由 `data/city-release.ts` 统一控制，发布状态不删除历史印章、收藏和停留位置。

西安处于筹备状态，不开放完整画卷切换，不把仅一篇内容作为整城体验。在「我的」续逛卡保留弱入口「下一城 · 西安筹备中」，点击半屏预告后可进入独立预告页，再阅读已经完成的永宁门。四张西安插画与数据保留，未完成画卷不出现在正式探索流。永宁门仍可收藏、登录盖章、分享和生成试读纪念册；单枚试读不宣称西安全城过半或集齐。西安没有印章时书架不展示空册，有试读记录时保留回看入口。旧西安城市详情、画卷分享转入预告页；旧永宁门和手册分享继续回看，不继承发送者进度。

西安使用暖砂宣纸、玄青正文、赤陶重点与琥珀金点亮反馈；四张画卷共用一套城市界面色。预告、地标详情、盖章反馈、集章册与探索手册延续这套视觉语言，朱红印章和收藏、盖章、分享操作与北京保持统一。

下一次城市版本计划**同时正式开放西安与哈尔滨**。西安在四张画卷的地标正文、插画、印章、收藏、手册和分享都完成后转为正式城市；哈尔滨先确定自己的画卷、地标清单与视觉语言，再按同一交付标准制作。两城及多城市流程均验收通过后一起提交新版本，不把只有封面或少数试读内容的城市算作正式开放。哈尔滨地标数及半城阈值以最终正式清单为准。

多城市正式开放后的用户流程：

1. 新用户从当前推荐城市开始；老用户默认回到**自己上次选择的城市与画卷**，更新版本不自动替他们换城。首次看到新版本时，可给一次轻量提示「西安、哈尔滨画卷已开放」，提供「去看看」和「继续当前城市」；关闭后不反复打断。
2. 画卷顶部的城市名可打开城市列表；「我的」城市册也能选城。北京、西安、哈尔滨均可随时进入和返回，无需读完前一城、达到半程或集齐印章。选城后记住当前城市及各城各自的画卷停留位置。
3. 地标阅读、收藏与盖章彼此独立。「半城足迹」按各城正式地标数向上取整计算，集齐后展示该城手册成册结果；两种奖励只记录本城探索成果，不承担解锁下一城的职责，也不自动切换首页。
4. 城市预告是**可选的阶段性入口**：只有插画和可交付内容足以让用户先体验时才展示。下一城尚未明确或尚无可看的内容时，城市列表只展示已开放城市，不循环挂一个空预告，也不承诺固定上新日期。

上线前先将选城、续逛、分享落地与发布状态由当前北京／西安的专门判断整理为多城市配置，再登记西安和哈尔滨的正式地标到云端目录，并同步客户端城市总数、半城阈值和集章册。保留已上线北京及西安永宁门试读的云端记录；检查旧分享链接、重复盖章、跨设备同步、每城手册与导出。完成代码验证和真机流程验收后再提交审核，不因修改客户端发布状态而跳过云端校验。

## 地标详情与内容标准

内容按「是什么 → 有什么值得看 → 到现场怎么观察」组织。每篇先选一个能讲清的主故事，再决定图片、段落和延伸入口。优先使用用户能在图上找出来、在现场认得出、讲给朋友也说得明白的细节。

故宫是完整详情的样板。其他地标按内容需要取用以下层次，短篇也应独立讲清一件事。

| 层次 | 写法 | 故宫示例 |
| --- | --- | --- |
| 核心名片 | 地标名、一句话概览、必要标签和头图，让用户在首屏认得这是什么 | 故宫的身份与建筑特点 |
| 趣味主故事 | 用一个细节串起正文，插画帮助用户观察、对照或数清 | 太和殿屋顶的第十只小兽，配有编号的走兽图 |
| 观察导览 | 给出看哪里、怎么找、前后有什么关系 | 从午门到神武门，沿中路观察建筑秩序 |
| 参观信息 | 有实际用途时再呈现，可折叠，保留官方入口与核对日期 | 预约、交通、附近的景山 |

现有内容有不同深度。故宫有完整导览，颐和园和水立方采用插画文章，其他入口目前使用分段地标故事或风物详情。水立方的水冰转换、南锣鼓巷的胡同生活等适合作为关联阅读。打磨时应保持操作与视觉语言一致，同时允许内容长度随主题变化。

天坛以“皇帝为什么到两个地方”为主问题，用清代正月祈谷与冬至祭天的安排，串起北侧祈年殿和南侧圜丘。配双景对照插画和南北辨认提示，地图、见闻回看及分享均进入这篇文章；详情与集章册共用三重檐祈年殿印章。旧见闻链接转至新正文，收藏和盖章沿用原编号。

永定门围绕城楼的消失与复建展开，区分历史城门和现存复建城楼，借原址复建、旧砖回归与中轴线关系解释城市记忆。配四处地标的南北关系插图及三条观察线索，明确瓮城、箭楼以地面标识表达；详情、收藏卡和集章册沿用同一地标编号，专属城楼印章共用模板。

颐和园 · 圆明园以两园今日景物的差异为主线，说明清漪园同遭毁损、后重修更名，以及西洋楼仅为圆明园一部分。配今日园景对照插图、两条观察线索，原颐和园专篇保留为延伸阅读。组合篇可独立收藏，沿用 `summer` 一枚地标印章和湖山双园图标，详情与集章册共用；不拆分旧记录，不改变北京19处地标总数。

正阳门箭楼围绕白色弧形遮檐展开一篇约两分钟的故事：箭窗的防御用途、近代增添的西式细节、前门交通变化和三条观察线索。配局部知识插图，86孔到94孔的变化作为小发现，收藏卡与分享优先使用这张插图。

知识图优先解释正文里靠文字难讲清的关系。历史与建筑细节在编写时核对，区分事实、解释和传说。参观政策等易变信息按官方渠道核对。正文读完后保留与当前内容直接相关的操作。

雍和宫以“从一串手串走近皇家寺院”为主线，区分小物件的纪念意义、材质观察与颜色功效，接续讲清王府、1725年行宫及1744年寺院的身份变化。配红墙下游客欣赏琉璃手串的生活情景插画，不作现场布局复原；观察点为名称身世及法轮殿藏式天窗。正文、收藏、同篇分享沿用 `lama` 地标，专属朱印以法轮殿屋顶意象和「雍和宮」落款构成，详情、集章册、探索手册及图片导出同步。

南锣鼓巷围绕“为什么像一条蜈蚣”讲清一条主巷、两侧各八条支巷的格局，以及街巷格局与房屋年代的区别。配能数清支巷的俯视水彩，说明形态作简化、非历史复原；雨儿胡同、帽儿胡同作为西侧公共街巷观察点，不承诺特定距离内一定安静。沿用 `hutong-lane` 地标与既有胡同专题延伸阅读，收藏回看、同篇分享及街巷纹样朱印贯通详情、集章册、探索手册和导出图片。

奥林匹克公园以“鸟巢和水立方为什么一圆一方”为主线，结合东侧鸟巢、西侧水立方的位置关系、钢构与气泡状外墙，以及2008、2022两届奥运用途。传统观念作为理解组合的一条线索，不替代赛事、结构和使用功能的设计原因。配有人散步的傍晚情景插图，鸟巢见闻和水立方完整文章作为延伸阅读。沿用 `olympic` 一枚组合印章，专属「雙奧」朱印以两座场馆轮廓构成，并同步收藏、同篇分享、集章册、探索手册及导出图片；子故事不额外计章，北京正式地标总数仍为19。

前门大街以铛铛车的告别与重来讲述城市记忆，区分1924年前门至西直门线路、1966年北京最后一条旧式有轨电车线路停驶与2009年元旦前门复古车重开，不将复古观光车当作连续运营的百年原车。配当代店铺、人流与乳白深棕电车的街景，西侧大栅栏与东侧鲜鱼口为商业街区观察线索，保留京味风物延伸入口。沿用 `qianmen` 一枚地标印章；「前門」朱印采用电车正面与轨道，共用于盖章、集章册、探索手册和导出图片，收藏及分享直达同一篇正文。

卢沟桥 · 宛平城围绕“桥与守护通道的城”展开，区分金代古桥、明末卫城及1937年七七事变的不同历史层次。石狮以大小和姿态为观察点，不以固定总数作知识目标；城墙弹痕须结合现场说明辨认，不把一般破损都解释为战争遗存。配今日石狮、联拱桥与桥东陆地上城门的和平生活情景，注明手绘不作精确比例或历史复原。沿用 `lugou` 一枚组合章，专属「盧溝宛平」朱印以桥与城门构成，同步收藏、同篇分享、集章册、探索手册和图片导出，已有印章不丢失。

首钢园从“大跳台旁的大烟囱是什么”切入，讲清原电力厂冷却塔、烟囱与高炉用途的区别，以及工业设施保留、新运动用途进入旧厂区的关系；“雪飞天”飘带曲线作为可观察的设计线索。插图采用湖岸傍晚、四座冷却塔、大跳台与日常步行场景，不描绘排烟、比赛或常年雪面，不把旧规划中的改造设想当成已实现功能。沿用 `shougang` 一枚地标章，专属「首鋼」朱印采用冷却塔和大跳台轮廓，同步详情、收藏回看、分享、集章册、探索手册与导出图片。

运河畔三座建筑以“粮仓、森林、船”的设计意象串联北京艺术中心、北京城市图书馆与北京大运河博物馆，区分古粮仓灵感与新建剧院、室内叶片顶棚与真实树林、博物馆休闲水街与大运河主河道。配外观—室内—外观的三联独立场景插图，不虚构连续地理全景；各馆参观安排分别以官方公告为准。沿用 `canal-culture` 一枚组合章，专属「運河文苑」朱印以粮仓屋脊、银杏叶、帆形轮廓构成，统一用于详情、集章册、探索手册及导出图片，并补齐收藏回看与同篇分享。

798 艺术园区以锯齿弧形屋顶与北向高窗为观察线索，讲述工业厂房的采光、空间与后来艺术创作和展览的联系，不将每栋建筑都概括为同一构造或采光方式。配有人气的红砖街巷与开放展厅情景插图，不对应具体展览或精确建筑复原。参观信息默认折叠，区分免费入园与具体展览预约、票务及拍摄规则。沿用 `art-798` 一枚地标章，专属「798」朱印采用连续弧形屋顶与窗格，同步收藏、分享、集章册、探索手册和导出图片。

三里屯太古里从“逛店为何常走到室外”切入，讲述现代独立楼体、开放街巷和小广场如何借鉴北京胡同与院落的空间组织，不将其表述为历史胡同改造。配傍晚有人散步聊天的玻璃楼体街巷情景插画，三个观察围绕开口、转角和停留空间展开；参观提示默认折叠，不依赖品牌名单、临时活动或固定店铺布局。沿用 `sanlitun` 一枚地标章，以两侧楼体、中间街巷及「三里屯」构成专属朱印，同步收藏、分享、集章册、探索手册和图片导出，保留已有进度。

隆福寺以“来隆福寺，寺在哪里”讲述古寺、文庙会、东四人民市场、隆福大厦与今天文化街区的不同历史层次，不把1993年商场火灾与古寺沿革混淆。配现代楼顶红墙金瓦院落与老城灰瓦屋顶相望的插画，明确隆福文化中心为仿古文化空间而非明代寺院原物，开放状态需另行确认；观察可以在街区开放区域完成，不要求登顶。沿用 `longfu` 一枚地标章，以中式屋檐、现代楼体基座和「隆福」构成专属朱印，同步收藏、分享、集章册、探索手册和图片导出，已有印章继续有效。

大兴机场以“为什么像海星”连接航站楼轮廓与旅客步行体验，讲清中央核心、五条登机指廊、陆侧交通连接区的不同功能，以及曲面支撑和天窗构成的内部空间。配鸟瞰—大厅双景独立插画，不画成规则五角星或六条登机指廊；不将设计中的步行时间宣传成值机安检登机的全流程保证。观察顺着实际乘机路线完成，出行提示折叠并区分大兴、首都两座机场及公共区、候机区。沿用 `daxing` 一枚地标章，以放射状航站楼和「大興」构成专属朱印，同步收藏、分享、集章册、探索手册和导出图片，旧记录继续有效。

### 地标细化的固定交付要求

以下要求适用于北京、西安及后续所有城市。每次细化直接沿用，无需重新设计操作流程。

- **制作顺序**：先提出主题与故事切口，由用户选择；再输出完整正文供用户确认；文案确认后，才据此设计插画、页面并实现代码。不得把主题确认当作文案确认。实施时保留已确认正文的知识与因果关系，调整核心内容须重新确认。
- **内容验收标准**：围绕一个核心问题讲透原因，用可核实的具体细节支撑，至少带走一个有记忆点的新认识，并知道在插画或现场看什么。阅读时长按实际篇幅标注，不为固定时长删去关键解释；避免空泛抒情、罗列数字和未经证实的戏剧化故事。

大明宫以“用空间读懂消失的宫殿”为主线：解释含元殿台基高差与殿前距离、考古遗存如何辨认建筑，并通过皇帝从北侧入殿纠正套用故宫形制的想象。配含元殿台基与淡墨宫殿叠影，观察围绕高差、朝向、遗存与展示的区别展开。事实依据包括文旅部大明宫介绍、西安科普网含元殿资料与[考古学者安家瑶访谈](https://www.thepaper.cn/newsDetail_forward_10981064)；插画为解释性艺术想象，不作考古复原图。

- **内容目标**：用户能迅速认得地标，读完说出一个新知道的细节，并能在插画、照片或现场辨认它。每篇选一个核心问题，围绕原因、故事与观察线索展开；避免仅罗列年代、规模，或使用通用的“感受历史”“看看轮廓”替代具体知识。篇幅由主题决定，不以增加字数作为完成标准。
- **基本结构**：一句话名片 → 一个好奇的问题 → 讲完整的主故事 → 帮助理解的图（需要时）→ 一个可观察的细节。复杂关系用插画解释，不机械套用文字示意图；不强制每篇都增加导览或参观信息。
- **事实与素材**：历史、建筑与冷知识先核对可信资料，区分事实、解释和传说。资料保留在内容元数据或代码注释中，正文不堆来源链接。必要的参观信息单独折叠并注明核对时间。新插画按城市规范目录管理。
- **收藏见闻**：每篇正式地标主故事均提供“收藏见闻 / 取消收藏”，保存的是该故事；在“我的见闻”使用同一标题与所属城市，点开直达原文。收藏、阅读、盖章相互独立，不新增“收下”“点亮知识”等同义操作。
- **盖印打卡**：复用统一印泥盒按钮、登录校验和云端写入；不限每日次数，同一地标只计一次，已盖章保持状态。新增或细化专属印章时，详情动效、已盖章状态和我的集章册共用同一素材或模板，不分别维护不一致的图案。组合地标与子故事的归属说明清楚，不重复计算印章。
- **分享**：分享故事直达这篇故事，标题与落地内容一致；分享画卷才进入画卷并定位地标。好友按自己的收藏和盖章记录展示，不继承发送者进度。复用微信分享入口，不另外增加一套分享流程。
- **交付验证**：检查地图进入 → 正文 → 收藏与取消 → 我的回看 → 登录盖章与重复盖章 → 返回地图反馈 → 分享落地。运行类型检查和现有冒烟测试；新印章同步核对详情与集章册。布局、插画加载及微信原生交互另做真机验收。

## 盖章、收藏与进度

| 记录 | 如何获得 | 在哪里看 |
| --- | --- | --- |
| 地标印章 | 在详情主动点「盖印打卡」，同一入口只记一次 | 首页点亮状态与进度、「我的」集章册 |
| 收藏见闻 | 在正式地标主故事详情点「收藏见闻」，可取消 | 「我的见闻」，可按城市筛选并打开原内容 |
| 城市印章 | 由有效探索记录获得，兼容既有的阅读、收藏和完整探索记录 | 「我的」折叠的其他记录 |
| 阅读记录 | 在提供已读动作的内容完成阅读，或保留旧章节记录 | 「我的」折叠的阅读记录与续看入口 |

地标详情打开时可以浏览，主动盖章后才点亮。待盖章时显示印泥盒样式的按钮。盖章成功时给出视觉反馈，支持的设备提供轻震。故宫首次盖章有专属落印动效；其他已细化地标从对应插画提炼可辨认的小图标制作专属朱印。详情盖章、已盖章状态、集章册、探索手册与导出图必须同步同一地标图案；永宁门采用宽城墙、箭楼屋檐与中央券洞。旧记录只更新显示，不要求用户重新盖章。

登录后可不限次盖章，同一个地标只计一次进度。云端保存成功后才播放动效，失败保留重试入口。旧额度字段仅保留作历史兼容，不再发放、扣减或展示。

正式开放城市按 `ceil(正式地标总数 × 50%)` 触发一次「半城足迹」里程碑。北京19处地标在第10枚章时，由云端事务确认一次提示，提供「翻开我的探索手册」与「继续逛北京」。半程提示不宣传城市解锁；新城市开放提醒与本城里程碑分开。已有里程碑标记继续有效，不重置、不重复弹出。集齐19枚仍提供完整手册入口。筹备城市试读保留盖章记录，但不展示整城进度奖励；正式城市可自由选择，不以过半作为探索门槛。

北京的印章进度和画卷停留位置登录后同步到云端，本机保留缓存。「我的」可恢复上次所在画卷。分享定位与个人续逛位置分开，朋友的链接不会携带发送者的收藏或印章。

## 我的 · 我的城市册

1. **续逛卡**展示当前城市插画、印章数量和上次停留的画卷。主操作继续探索当前城市，卡片下方提供选城入口。
2. **地标集章册**按城市切换，城内按画卷分册，以三列网格展示。已盖章用朱印，待盖章用灰色问号，点任一格可打开该地标。北京早期印章收纳在独立分册，不计入当前 19 处进度。默认展示最近探索的正式城市；筹备城市标签注明「筹备中」，已有试读印章单独保留，不按试读总数宣称全城集齐。此前正式城市集齐后标为「已完结」，未集齐的可继续探索。
3. **我的见闻**保留图文卡流，卡片标注所属城市，支持「全部」与已收藏见闻的城市筛选；取消该城市最后一则收藏后重置为「全部」。点卡片可回到原内容；待发现见闻在折叠入口内。
4. **其他记录**折叠展示城市印章、阅读记录和成就。中轴线书签存档保留，城市册里已移除独立的发现书签卡片。

## 城市探索手册

「我的」以横向书架展示正式城市和已有试读印章的筹备城市，一城一本，各城沿用自己的画卷色调。当前筹备西安展示为试读纪念册，不因唯一开放地标已盖章而显示全城圆满。空册可以打开，第一枚正式地标印章获得后自动生成第一张内页，无需集齐或编辑。集章册仍用于进度与地标查找，手册用于翻阅纪念。

手机竖屏一屏一页，左右手动翻阅封面、已盖章地标内页、待续或成册落款页。纸纹、装订线、纸边与阴影共同营造书籍感。内页复用地标插画、共用朱印及一句发现，可重读原故事；专门的知识插图完整呈现。按已有印章记录顺序收录正式地标并去重，历史独立印章仍在原集章册保存。当前账本没有可靠的逐枚日期，不补造到访时间，也不把线上盖章称作实地到访。

- 默认「导出我的探索手册」生成1500×2100 JPG封面，含城市插画、最多三枚本人已有印章、一句发现。少于三枚如实展示；空册不能导出收集成果。
- 可保存当前地标单页（1500×2100），也可导出全部内页长图。每段最多四页，输出1200×1680至1200×6720 JPG，逐张保存，避免无限高度画布；失败显示已保存张数，可检查相册权限后重试。
- 微信会话或朋友圈的小程序分享携带本次主动分享的正式地标编号快照，朋友可直接翻阅整本已分享手册，不继承发送者的印章、收藏或阅读状态；接收者自己的手册始终读取本人记录。快照不会随发送者后续盖章自动增加。
- 导出的普通JPG不携带可点击链接或小程序码，图中提供「大千小卷」搜索提示；直达完整手册使用页面的微信分享入口。
- 原独立明信片产品入口及生成器已移除，已发出的旧链接转入北京探索手册。每座城市集齐当前正式地标后，在盖章结果中提供手册入口和成册提示；不另造一套奖励数据。

第一版是系统自动生成的探索纪念册；照片、私人文字、真实旅行日期和实体印制暂不提供。

## 分享

- **画卷分享**使用当前画卷和一个推荐地标。朋友打开后看到对应画卷、推荐标签和地标高亮，可以点推荐直接进入，也可以自行选别处。
- **内容分享**按页面类型落地。故事分享链接直达对应内容，画卷分享链接进入对应画卷并定位地标。收件人的探索、收藏和盖章由自己的操作产生。

## 页面打磨清单

优先从能影响首次体验的入口开始，按「画卷 → 地标详情 → 盖章回流 → 我的 → 认识北京 → 分享落地」逐页核对。

| 页面或环节 | 验收重点 |
| --- | --- |
| 画卷首页 | 常见屏幕比例下，横滑稳定，地标标签易点、不遮住关键画面；第一次打开能看懂可以做什么。 |
| 地标详情 | 首屏认得地标，读完能说出一个具体发现；按完整导览、插画短篇、分段故事各抽查一页。 |
| 盖章回流 | 首次盖章、已盖章展示、返回定位、第 10 枚提示各走一次，检查动效和计数。 |
| 我的 | 空状态、部分盖章、集齐、筛选后无收藏、重开续逛均能顺利操作；手机上检查网格和长标题。同步核对旧中轴线互动页的「查看我的发现书签」去向。 |
| 认识北京 | 城名、历史、城市格局和深读各有明确用途，能从读过的内容回到探索。 |
| 分享落地 | 从微信会话打开画卷和详情链接，检查推荐定位、返回行为和个人进度隔离。 |

每次打磨选一个页面和一个可观察的问题，用北京样板走通后再扩到同类页面。提交前运行 `npm run typecheck` 和 `npm run test:smoke`；布局、手势、盖章动效与微信分享额外做真机验收。

## 扩展边界

- **新城市**随完整画卷、可读地标故事、独立的印章与续逛进度一起接入。上架城市和旧资料条目分开管理。
- **全国足迹**等有多座城市上线后再设计，可从「我的」的护照式总览进入中国地图，展示已经探索的城市。
- **专属游记**预留在「我的」的见闻与其他记录之间。后续可在探索手册上增加用户照片、私人文字和旅行日期，当前不提供编辑、上传及实体印制入口。
- 宠物、知识问答与旧城市入口保留相应路由兼容。当前主流程以画卷、地标故事、主动盖章和收藏回看为准。

## 云开发与记录保存

- 环境：`cloud1-d7gp1zt48d1eda997`。内容索引随小程序发布，37 张画卷、封面和内容插画通过 `services/cloud-assets.ts` 映射到 `cloud-assets/` 云目录。本地原件统一放在 `artwork/cloud-assets/cities/{city}/scrolls|landmarks|stamps`，封面在 `shared/covers`，资源清单及校验值在 `artwork/cloud-assets-manifest.json`。上传包排除已迁移的大图，Tab 图标仍随包发布。
- 云端图片统一存放在 `cloud-assets/cities/{city}/scrolls|landmarks|stamps` 和 `cloud-assets/shared/covers`，资源映射已切换到这些目录。页面沿用稳定的资源键，由映射函数生成新 File ID。新增插画先按规范目录上传，再同步登记资源映射和校验清单。
- 部署：在 `cloudfunctions/exploration` 执行 `npm ci`、`npm run build`，再上传部署 `exploration`（云端安装依赖）。入口是构建出的 `index.js`，地标白名单为 `catalog.json`，构建时由 `scripts/build-cloud-catalog.cjs` 从已上线城市注册表自动生成，区分正式地标和历史独立印章。
- 数据库初始化：创建 `explorers` 集合，将权限设为「仅管理端可读写」，即自定义规则 `{"read":false,"write":false}`。客户端只通过云函数读写，印章和里程碑不得开放客户端直接修改。云存储插画供所有用户读取，写入只由管理端进行。
- 游客可看画卷和内容、收藏见闻。主动盖章先进入微信账号登录页，成功后返回原页；「我的」也有登录入口，无需头像、昵称或手机号。
- 首次登录先将本机所有 `dqxj_` 记录备份到 `dqxj_cloud_guest_backup_v1`，再发送固定迁移编号。云函数按微信身份保存数据，将旧印章、收藏和阅读记录合并进账号，并留存该次迁移原值。已有账号从第二台设备迁移时合并内容，保留旧账本字段；同一迁移重试不重复计入印章。
- 云端确认成功后才停用旧印章数组，迁移回执在 `dqxj_cloud_migration_receipt`。失败保留备份及原记录，下次登录可重试；不要通过清缓存测试迁移。
- 登录后的收藏、阅读与续逛位置经过持久队列同步。断网保留待同步操作，前台重开时重试。不同设备的收藏按增删合并，响应版本用于防止旧快照覆盖新进度。
- 盖章由云函数事务去重写入，不限制每日次数；同一事务按当前城市正式地标数的 50% 确认里程碑，每城只触发一次，防止多设备并发重复触发。后来增加地标不会撤销已获得的奖励。服务器身份来自微信运行上下文。
- 自动检查：`npm run typecheck` 和 `npm run test:smoke`。冒烟检查通过 SDK 边界适配器执行已编译的云函数，覆盖登录、备份、跨设备迁移、并发收藏、失败重试、不限次盖章与十枚奖励；另覆盖手册生成、旧链接迁移及朋友快照隔离，不访问真实用户数据。`npm run test:handbook` 使用真实插画与 Canvas 2D 执行正式手册导出函数，检查北京、西安封面、完整单页及分段长图，生成本机预览（Windows 中文字体）。图片加载、微信登录、盖章动效和相册授权仍需真机验收。
